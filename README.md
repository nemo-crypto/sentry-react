# React Sentry 监控接入示例

本目录保存 [sentry.js](sentry.js) 配置片段，原记录对应Sentry服务端24.9.0与 `@sentry/react` 8.31.0。没有React应用脚手架、package.json或Sentry服务端部署工程，需要集成到现有React项目。

## 示例涉及的能力

| 能力 | 源码内容 | 接入要点 |
|---|---|---|
| 错误与事件 | init、captureEvent等片段 | 对齐宿主事件和错误边界 |
| 页面性能 | browserTracingIntegration | 核对路由、采样与实际请求 |
| 性能分析 | browserProfilingIntegration | 核实浏览器、SDK与部署条件 |
| 会话重放 | replayIntegration与重放采样 | 核对隐私遮罩和数据采集范围 |
| 业务上下文 | 用户、tag、extra、beforeSend | 只传必要业务字段，避免放入凭据 |

## 如何集成

先在宿主工程安装与此示例相符的SDK版本，再将所需配置整理到宿主的客户端初始化入口。配置文件里存在多次Sentry.init及不同用途的片段，不能原样多次初始化；应合并成一套适合宿主的配置。

需要核实：项目DSN、环境名称、release/构建标识、采样率、路由集成和重放设置。源码含 `environment: process.env` 的写法，接入时应明确提取环境名称字符串，不能把整个环境对象当作环境标识。

## 采样与验证

当前片段设置了性能追踪/分析高采样与错误重放参数，不能未经评估直接作为团队所有环境的默认配置。验证时用独立测试事件确认归属项目、环境、版本、上下文及错误堆栈，再检查性能与重放是否实际入库。

本目录没有构建、单测或服务端启动命令。本轮只核对示例结构，不连接Sentry、不发送事件，也不将原版本记录视为当前推荐或已验证的兼容组合。
